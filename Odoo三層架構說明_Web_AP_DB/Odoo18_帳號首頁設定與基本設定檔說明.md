## 第一部分：設定帳號登入後「預設首頁為特定模組」

### 1.1 核心概念：Home Action (首頁動作)
在預設情況下，使用者登入 Odoo 後會看到「所有應用程式選單（App Drawer）」或「討論（Discuss）」模組。
Odoo 內部是透過使用者資料表上的 **`action_id`（主頁動作 / Home Action）** 欄位來決定登入後的重導向畫面。只要將該欄位指向目標模組的「Window Action（視窗動作）」，即可讓使用者一登入就直接開進該模組的儀表板或清單頁。

---

### 1.2 方法一：透過 Odoo 介面圖形化設定（最推薦，免寫程式）

> ⚠️ **前置關鍵步驟**：必須先啟動**「開發者模式 (Developer Mode)」**，否則使用者介面會將 `Home Action` 欄位隱藏！

#### 步驟 1：啟動開發者模式
1. 以管理員（`admin`）帳號登入 Odoo 18。
2. 進入 **設定 (Settings)**。
3. 頁面滾動到最底部，點選 **「啟用開發者模式 (Activate the developer mode)」**。
4. 網頁重新整理後，右上角會出現一個 🐞 小蟲圖示，代表啟用成功。

#### 步驟 2：進入使用者管理畫面
1. 前往 **設定 (Settings)** ➔ **使用者與公司 (Users & Companies)** ➔ **使用者 (Users)**。
2. 點選您要自訂首頁的特定帳號（例如某門市人員、資產管理員或您自己的帳號）。

#### 步驟 3：設定首頁動作 (Home Action)
1. 在使用者詳細資料頁中，切換到 **「偏好設定 (Preferences)」** 分頁。
2. 找到 **「主頁動作 (Home Action)」** 欄位（因為開啟了開發者模式，此欄位才會出現）。
3. 點選下拉選單：
   * 點選 **「搜尋更多 (Search More...)」**。
   * 輸入您想要設為首頁的模組名稱（例如輸入：`資產`、`Assets`、`Inventory` 或 `Sales`）。
   * 選擇該模組的主要視窗動作（通常名稱會是該模組主清單，例如 `資產列表 (Assets Action)` 或 `資產總覽`）。
4. 點選左上角手動儲存（雲端圖示）。

#### 步驟 4：驗證成果
登出目前帳號，重新使用該帳號登入，系統會自動繞過討論模組，**直奔您設定的目標模組首頁**！

---

### 1.3 方法二：將特定模組設為「所有新建立帳號」的預設首頁

如果您希望之後**每建立一個新員工帳號，預設首頁都是該模組**，可以使用 Odoo 的「設定預設值」功能：

1. 保持在開發者模式下。
2. 進入任一使用者的 **偏好設定 (Preferences)** 分頁。
3. 將 **主頁動作 (Home Action)** 選好目標模組。
4. 點選右上角的 🐞 **開發者小工具圖示**。
5. 點選 **「設定預設值 (Set Defaults)」**。
6. 設定條件：
   * 欄位：`主頁動作 (action_id)`
   * 條件：選擇「所有使用者通用 (All users)」。
7. 點選儲存。之後新建立的使用者都會自動套用此首頁。

---

### 1.4 方法三：透過自訂模組 (XML/Python) 以程式碼綁定

如果您在開發客製化模組（例如資產管理串接模組），想在模組安裝時自動將某群組/使用者的首頁設定好，可以在自訂模組中撰寫：

```xml
<!-- 在模組的 data/default_home_action.xml 中定義 -->
<odoo>
    <data noupdate="1">
        <!-- 找到目標使用者（例如 admin），綁定其 action_id -->
        <record id="base.user_admin" model="res.users">
            <field name="action_id" ref="your_module_name.action_asset_management_main_view"/>
        </record>
    </data>
</odoo>
```

## 第二部分：Odoo 18 核心設定檔 (odoo.conf) 詳解

Odoo 的核心設定檔通常位於 `/etc/odoo/odoo.conf`（本機安裝）或 `/opt/odoo18/config/odoo.conf`（Docker 掛載）。

### 2.1 標準生產環境 odoo.conf 範本

以下是一份經過安全性加固與效能調校的完整設定範本：

```ini
[options]
; ==============================================================================
; 1. 核心安全與權限
; ==============================================================================
; 資料庫管理介面主密碼 (Master Password)，用於建立/備份/刪除資料庫，至關重要！
admin_passwd = YourSuperSecureMasterPassword2026!

; 是否允許在登入頁面列出所有資料庫清單 (生產環境建議設為 False，防止庫名外洩)
list_db = False

; 資料庫過濾正則表達式 (若同一 DB 伺服器有多個庫，鎖定特定網域存取特定庫)
; dbfilter = ^%d$

; ==============================================================================
; 2. 資料庫連線配置 (連接 VM 3 Odoo DB)
; ==============================================================================
db_host = 192.168.1.130
db_port = 5432
db_user = odoo
db_password = OdooDbStrongPass123
db_maxconn = 64
db_name = False

; ==============================================================================
; 3. 模組載入路徑
; ==============================================================================
; 逗號分隔：第一個為系統原生模組，第二個為掛載的自訂模組目錄
addons_path = /usr/lib/python3/dist-packages/odoo/addons,/mnt/extra-addons

; ==============================================================================
; 4. 網路與反向代理 (搭配 Nginx)
; ==============================================================================
; 當前方有 Nginx 反向代理負責 HTTPS 時，此項必須為 True
proxy_mode = True

; 內部監聽埠號
http_port = 8069
http_interface = 0.0.0.0

; ==============================================================================
; 5. 效能與多行程併發 (Workers 模式)
; ==============================================================================
; Worker 數量計算公式：(CPU 核心數 * 2) + 1。0 代表單行程除錯模式。
workers = 5

; 背景排程工作 (Cron Jobs) 專用執行緒數 (建議 2)
max_cron_threads = 2

; 限制單一 Worker 記憶體使用量 (Soft: 超過時在該請求結束釋放 / Hard: 超過直接重啟該 Worker)
limit_memory_soft = 2147483648       ; 2 GB
limit_memory_hard = 2684354560       ; 2.5 GB

; 單一請求 CPU 運算最大秒數與實體執行最大秒數 (防止卡死的慢查詢拖垮主機)
limit_time_cpu = 600
limit_time_real = 1200
limit_request = 8192

; ==============================================================================
; 6. 檔案與儲存路徑
; ==============================================================================
; 存放 session、圖片、PDF 與附件檔案的路徑 (對應到 Volume 掛載)
data_dir = /var/lib/odoo

; ==============================================================================
; 7. 系統記錄檔 (Logging)
; ==============================================================================
; 日誌級別: debug_sql, debug, info, warn, error, critical
log_level = info
; 若使用 Docker，一般輸出至 stdout (留空)；若為原生安裝可指定日誌路徑:
; logfile = /var/log/odoo/odoo-server.log
```

### 2.2 關鍵參數分類解析

| 參數名稱 | 建議值 | 功能與重要性說明 |
| :--- | :--- | :--- |
| **`admin_passwd`** | 高強度隨機密碼 | **最高機密**。進入 `/web/database/manager` 建立、還原、複製、刪除資料庫的唯一憑據，千萬不能使用預設值。 |
| **`proxy_mode`** | `True` | **必設**。啟用後 Odoo 才會讀取 Nginx 送來的 `X-Forwarded-For` 與 `X-Forwarded-Proto` 標頭，正確識別使用者真實 IP 與 HTTPS 狀態（若沒設會導致 CSS 跑版或 HTTPS 轉址無窮迴圈）。 |
| **`workers`** | 4 ~ 9 (視 CPU 調整) | **效能核心**。設定大於 0 會啟動 Gunicorn 多進程架構，能夠同時處理多個使用者的併發點擊與排程任務。 |
| **`list_db`** | `False` (正式環境) | 正式上線後設為 `False`，使用者無法在登入畫面點擊「Manage Databases」，防止惡意探索。 |
| **`addons_path`** | 逗號隔開的多個路徑 | Odoo 掃描模組的目錄清單。新開發的「資產管理串接模組」放置於自訂路徑後，此參數必須包含該路徑才能載入。 |
| **`limit_time_real`** | `1200` (秒) | 報表產生與大量資料匯入時的超時保護。預設值往往過短（120秒），大型 Excel/PDF 匯出時常會報錯，建議調高。 |

## 第三部分：實務除錯與注意事項

1. **改了 `Home Action` 卻沒有生效？**
   * **原因**：使用者瀏覽器有 Session 快取，或該使用者沒有目標模組的「存取權限 (Access Rights)」。
   * **解決**：請確認該使用者所屬的安全群組（Security Groups）有權限查看該模組，並請使用者**登出後重新登入**（或按 `Ctrl + F5` 強制重新整理）。

2. **在 Docker 環境下修改 `odoo.conf` 如何套用？**
   * 在 VM 2 的工作目錄下執行重啟指令：
     ```bash
     cd /opt/odoo18
     sudo docker compose restart odoo
     ```

3. **忘記了 `admin_passwd` 怎麼辦？**
   * 直接開啟 `odoo.conf` 編輯該檔案，把 `admin_passwd =` 後面的字串改成新密碼，重啟 Odoo 服務即可立刻生效覆寫。
